QMS OPERATING MODEL

PLAN → DEFINE → EXECUTE → VERIFY → MEASURE → REPORT → IMPROVE

The QMS manages the quality of building and maintaining the banking application. It is not the banking application itself.

METRICS & GOVERNANCE

Recommended measures

MetricFormula / interpretationWhy it matters
Test pass ratePassed tests ÷ executed tests × 100Shows current test outcome; report blocked tests separately.
Critical open defectsCount of Critical defects not closedRelease blocker; target is zero.
Requirements approval rateApproved in-scope requirements ÷ total in-scope requirements × 100Reveals ambiguity and approval gaps before coding.
Defect leakageDefects found after release ÷ all defects found across the measured lifecycle × 100Indicates whether earlier reviews and tests are effective.
Defect resolution timeAverage time from logging to verified closureHighlights delays, especially for Critical/High defects.
Requirements-to-test traceabilityRequirements linked to test cases ÷ total requirements × 100Helps prove each important business rule was verified.
Reopen rateReopened defects ÷ defects marked fixed × 100Signals weak fixes or inadequate retesting.
Unresolved high-severity defects: document customer/financial impact, likelihood, affected transactions, compensating controls, responsible owner, target date, and residual risk. Obtain written acceptance from authorized business, risk, and security stakeholders as applicable. Critical financial-integrity or severe security defects should block release; an informal verbal approval is not sufficient.
